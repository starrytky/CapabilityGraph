## 2. 信息架构

三个主 Tab，一个管理后台（非用户端）。

```
今日 ─── 今日分卡 ──── 三项分解
      ├─ 今日三件事 ── 还债 / 补缺口 / 拓宽
      ├─ 快速记一笔 ── 五类证据统一入口
      └─ 休息日 / 补卡

地图 ─── 六区列表 ──── Topic 折叠 ── 节点详情
                                  ├─ 分层掌握度
                                  ├─ 证据时间线
                                  ├─ 自测 / 讲解入口
                                  └─ 误区辨析

我的 ─── 趋势（热力 + 折线）
      ├─ 周报
      ├─ 可讲清清单
      ├─ 数据导出
      └─ 提醒与目标设置

后台 ─── 节点管理 / 题库管理 / 权重维护
```

**为什么是三个 Tab**：产品只有三件事可做——看今天的账、推进地图、回看趋势。任何第四个 Tab 都会变成"内容推荐"或"社区"，那会把产品拉回课程 App 的赛道。

## 4. 功能详述

每个功能统一按：**入口 → 前置 → 交互 → 规则 → 输出 → 异常 → 验收**。

### F1.1 今日评分卡

- **优先级**：P0｜**版本**：v0.1
- **入口**：App 打开后默认落地页「今日」Tab 顶部。
- **前置**：当日尚未标记为休息日。
- **展示内容**：
  1. 今日分数（大号数字）+ 档位文案；
  2. 三项分解：增量 `I` / 巩固 `R` / 结构 `S`，各显示实际得分与满分（60 / 25 / 15）；
  3. 一句话点评（由当日证据生成，模板化，非 LLM）；
  4. 昨日与近 7 日均分，用于对照（不显示"击败 xx% 用户"）。
- **规则**：
  1. 分数在证据入账后**实时重算**，不做延迟批处理；
  2. 当日 23:59 后分数冻结，不可再变；
  3. 当日无任何证据 → 显示"今天还没有证据"空态，**不显示 0 分**；
  4. 分数档位文案固定五档（见 §7.1），不做随机化、不做夸张措辞；
  5. 三项分解必须可点开，展开后列出"这 60 分里的每一条证据"——任何分数都要能追溯到具体事件。
- **输出**：影响今日分卡、我的-趋势、周报。
- **异常**：
  - 计算失败 → 显示"分数计算中"+ 重试按钮，**不显示 0**（0 会被误读为惩罚）；
  - 证据刚入账但分数未刷新 → 强制刷新一次，仍失败则提示"已记录，分数稍后更新"。
- **验收**：
  - Given 今天提交了一条 D1 证据（强度 0.2），When 返回今日页，Then 分数 > 0 且点击分解能看到这条证据；
  - Given 今天没有任何证据，When 打开今日页，Then 显示空态文案，且不出现数字 0；
  - Given 23:59 之后修改历史证据，When 查看今日页，Then 昨日分数不变。

### F1.2 今日三件事

- **优先级**：P0｜**版本**：v0.1
- **入口**：今日页第二区块，固定 3 张卡。
- **前置**：图谱中至少存在 5 个 `M_eff > 0` 的节点（否则走"起步模式"，见异常）。
- **每张卡展示**：
  - 槽位标签（还债 / 补缺口 / 拓宽）；
  - 节点名 + 一句"为什么是它"（逾期天数 / 前置已满足 / 与你最近在学的相邻）；
  - **预计贡献区间**（如"+6 ~ +9 分"）与预估耗时；
  - 主按钮"开始"。
- **规则**：
  1. 永远只给 3 个，不提供"换一批"以外的更多选项；"换一批"每天上限 3 次；
  2. 排序与候选池见算法文档 §5，产品侧不引入额外人工干预；
  3. 卡片完成后置灰并显示"已完成"，**不自动补位**（补位会诱导无限刷分）；
  4. 三件事全完成且当日分 < 60 时，底部出现"加练"入口（打开复习队列），否则不出现；
  5. 预计贡献必须是区间，禁止显示精确值（精确值会诱发为 0.5 分反复尝试）。
- **异常**：
  - **起步模式**：节点数不足时，三张卡替换为"从这两个区任选一个节点开始"，不做推荐；
  - 推荐结果为空（理论上不应发生）→ 显示复习队列入口；
  - 某节点被后台废弃 → 该卡静默替换为次优候选，不弹提示。
- **验收**：
  - Given 有 3 个逾期节点，When 打开今日页，Then 第一张卡为还债槽且显示逾期天数；
  - Given 已完成第 1 张卡，When 返回今日页，Then 该卡置灰，第 4 位不会出现新卡；
  - Given 三张卡全部完成且当日分 48，When 返回今日页，Then 出现"加练"入口。

### F1.3 快速记一笔（证据统一入口）

- **优先级**：P0｜**版本**：v0.1
- **入口**：今日页悬浮按钮、节点详情页"添加证据"、复习卡完成后。
- **前置**：需先选定节点（可从搜索、最近访问、地图选择）。
- **交互（3 步内完成）**：
  1. 选节点（默认带出最近 3 个节点，支持搜索）；
  2. 选证据类型（五类，图标 + 一行说明）；
  3. 按类型补充最少信息 → 提交。
- **各类型的必填项（硬性）**：

| 类型 | 必填 | 选填 | 耗时目标 |
|---|---|---|---|
| 读过了 | 无（一键） | 笔记链接 | 5 秒 |
| 做了自测 | 进入答题（F2.1） | — | 90 秒 |
| 写了示例 | 代码或仓库链接 | 一句话说明 | 5 分钟 |
| 修了 bug / 做了决策 | 链接（commit/PR）+ 一句话 | — | 30 秒 |
| 讲明白了 | 进入讲解（F2.3） | — | 3 分钟 |

- **规则**：
  1. 表单字段**不得超过 3 个**（超过则录入率会崩，这是硬约束）；
  2. `demo` / `fix` / `design` 无链接时，强度自动降级为 0.3，并在提交后提示"补上链接可提升强度"；
  3. 提交后 **5 分钟内可撤销**，撤销即重算当日分与掌握度；
  4. 同日同节点同难度的重复证据，只取最大值（去重对用户透明，不提示"忽略"以免困惑）；
  5. 被前置门禁打折时，提交结果页显示"该证据按 50% 计入（前置掌握度 48/60）"，**给出原因，但不阻止**。
- **输出**：`evidence` 新增一条；`mastery` 更新；当日分重算；节点详情时间线更新。
- **异常**：
  - 离线 → 存入本地队列，恢复后按提交时间顺序补传，**不重算历史日的分**（只计入当天）；
  - 链接无法访问 → 不阻断提交，标记 `unverified`，强度 ×0.8；
  - 重复提交同一条证据（误触）→ 5 分钟内视为撤销重提，不产生两条。
- **验收**：
  - Given 选择"修了 bug"但未填链接，When 提交，Then 成功且强度为 0.3，并出现补链接提示；
  - Given 提交后 2 分钟内撤销，When 查看今日分，Then 分数回退到提交前；
  - Given 离线提交一条证据，When 恢复网络，Then 该证据入账且计入当天（不是补传当天）。

### F1.4 休息日标记

- **优先级**：P0｜**版本**：v0.1
- **入口**：今日页右上角菜单「今天休息」。
- **规则**：
  1. 标记后当日不计分、不计入周均分分母、**不中断任何连续记录**；
  2. 可撤销，撤销后当日恢复为"无证据"状态；
  3. 单周标记上限 3 天，超出后菜单置灰并提示"本周已休 3 天"（上限是为了让分数保持信息量，不是为了惩罚）；
  4. 标记后今日页整体变为浅色空态 + 一句话："休息也是计划的一部分。"
- **异常**：当日已有证据 → 弹确认"今天已有 2 条证据，标记休息会保留证据但不计分"。
- **验收**：
  - Given 标记休息，When 查看本周均分，Then 分母不含该日；
  - Given 本周已休 3 天，When 再次点击，Then 菜单置灰并提示上限。

### F1.5 补卡

- **优先级**：P1｜**版本**：v0.2
- **入口**：今日页空态下方「补记昨天」；或趋势页点击某一天的空格子。
- **规则**：
  1. 只允许补 **7 天内**且当日无证据的日期；
  2. 补卡必须带至少一条证据（不允许"只填个分"）—— 否则补卡会变成编分数；
  3. 补卡产生的证据标记 `backfilled = true`，在时间线上以"补记"角标区分；
  4. 补卡日的分数上限为 80（不能靠回忆刷出满分日）；
  5. 已被标记为休息日的日期不可补卡。
- **验收**：
  - Given 8 天前的空白日，When 尝试补卡，Then 入口不可用并提示仅支持 7 天内；
  - Given 补卡提交一条 D2 证据，When 查看该日分数，Then 分数 > 0 且 ≤ 80；
  - Given 无证据仅输入数字，When 提交，Then 被拒绝。

### F2.1 自测答题

- **优先级**：P0｜**版本**：v0.1
- **入口**：节点详情"测一测"、三件事卡、快速记一笔的"做了自测"。
- **前置**：该节点存在当层可用题目，且 30 天内未做过同一组题。
- **交互**：
  1. 一组 3 题，单题一屏；
  2. 顶部有总计时（2 分钟），超时自动提交；
  3. 提交后逐题给"对/错 + 为什么"，错误的题展示对应误区；
  4. 结果页显示本次获得的证据强度与掌握度变化。
- **规则**：
  1. 3 题全对 → 强度 0.4（`quiz`）；2 题对 → 0.2；1 题及以下 → 0，但**不显示"失败"**，显示"这组还不够，换一组"；
  2. 每题必有一个干扰项来自该节点的 `misconceptions`；
  3. 同一组题 30 天内不重复；题库耗尽时提示"该节点题目已做完，试试写个示例或讲一遍"；
  4. 允许申诉判错，申诉后进入待复核队列，复核通过则恢复强度并记录（用于改进判卷）。
- **异常**：中途退出 → 不保存，不消耗题目冷却；断网 → 题目本地缓存，提交失败则保留答案待重试。
- **验收**：
  - Given 3 题全对，When 查看结果，Then 获得 0.4 强度且掌握度 D1 层进度上升；
  - Given 同一节点今日已做过一组，When 再次进入，Then 换用另一组题；
  - Given 全部题库已用完，When 进入自测，Then 提示引导到示例/讲解证据。

### F2.2 最小示例提交

- **优先级**：P0｜**版本**：v0.1
- **入口**：节点详情、三件事卡、快速记一笔。
- **交互**：粘贴代码 / 贴仓库或 CodePen 链接 + 一句话说明"这个示例证明了什么" → 提交。
- **规则**：
  1. 强度 0.6（`demo`），计入 D2 层；
  2. 一句话说明少于 10 字 → 强度降为 0.4（说明是"我真的理解"的唯一低成本替代）；
  3. 支持 Markdown 粘贴，自动识别语言；
  4. 代码内容**只存哈希与长度用于去重，不持久化全文**（隐私，见 §9.2）。
- **异常**：链接失效 → 保留证据但标记 `unverified`，强度 ×0.8，节点详情显示"链接已失效"。
- **验收**：
  - Given 提交代码 + 15 字说明，When 成功，Then 强度 0.6 且计入 D2；
  - Given 提交代码但说明 5 字，When 成功，Then 强度 0.4 并提示补充说明。

### F2.3 AI 讲解对练

- **优先级**：P1｜**版本**：v0.3
- **入口**：节点详情"讲一遍"、快速记一笔的"讲明白了"。
- **前置**：该节点存在 `misconceptions` 与 `canonical_answer`。
- **交互**：
  1. 提示"用 3 分钟讲给一个完全不懂的人"；
  2. 用户文字或语音输入（语音转文字后**必须允许编辑**再提交）；
  3. AI 以"初学者"身份追问 3 层，每层一问，用户可回答或说"我不确定"；
  4. 结束后给出四维评分（准确 / 边界 / 类比 / 抗追问）+ **每条扣分引用用户原话**。
- **规则**：
  1. 总分 < 60 不计证据；60–79 计 0.4；80+ 计 0.6 且可计入 D4（算法文档 §3.2）；
  2. 被追问后改口超过 2 次，总分 -10；
  3. AI 措辞禁止出现"你答错了"，统一改为"这里我没听懂，能换个说法吗"；
  4. 评分必须锚定原话；无法锚定的扣分项作废（防止 AI 幻觉式扣分）；
  5. 单次对话轮数上限 12 轮，超出强制结束并给分。
- **异常**：
  - AI 超时 / 失败 → 保留用户输入，提示"这次没评上，内容已存草稿"，不计证据；
  - 语音识别失败 → 回退为文字输入。
- **验收**：
  - Given 讲解 80 分，When 查看结果，Then 获得 0.6 强度且可计入 D4 层；
  - Given AI 返回的扣分未引用原话，When 渲染结果，Then 该扣分项不显示；
  - Given 对话 12 轮，When 继续回答，Then 强制结束并给分。

### F2.4 真实工作回填

- **优先级**：P1｜**版本**：v0.2
- **入口**：快速记一笔的"修了 bug / 做了决策"；支持从 Git 提交列表批量导入（可选）。
- **规则**：
  1. `fix` 强度 0.8（D3），`design` 强度 1.0（D4）；
  2. 必填链接（commit / PR / 文档）+ 一句话说明，缺链接降为 0.3；
  3. 提交 D3 以上证据时，**30% 概率**触发误区辨析抽查（F3.4），答错则该证据强度 ×0.5；
  4. 同一 commit 只能绑定一个节点（避免一鱼多吃）。
- **验收**：
  - Given 提交 D3 证据并命中抽查且答错，When 查看掌握度，Then 该证据强度为 0.4；
  - Given 同一 commit 绑定第二个节点，When 提交，Then 被拒绝并提示已绑定。

### F2.5 复习卡（还债）

- **优先级**：P0｜**版本**：v0.1
- **入口**：今日页三件事的第一槽、地图页"待还"筛选、今日页"加练"。
- **前置**：存在 `M_eff > 0` 且距上次复现超过 `0.4 × h` 的节点。
- **交互**：一屏一张卡：节点名 + "多久没碰 / 掌握度掉了多少" + 「还记得吗？」→ 出示一道复现题（不是重学材料）→ 用户作答 → 给出结算。
- **规则**：
  1. 复现结果分四档，对应 `strength` 与下次间隔（算法文档 §3.2 的 `review` 语义）：

| 自评结果 | 强度 | 下次间隔 |
|---|---|---|
| 完全想不起 | 0.0 | 1 天（重新入队） |
| 想起来但写不出 | 0.4 | 3 天 |
| 能写但要查文档 | 0.7 | 7 天 |
| 不用查就能写 | 1.0 | 间隔翻倍 |

  2. 逾期越久，还上越值分（`k_due` 已含在公式里，界面不需解释公式，只显示"+9 分"）；
  3. 逾期超过 `3 × h` 的节点不再显示为"逾期"，转入"待重建"分组，卡片文案改为"这个能力可能已经生疏了，重新学一遍"，**去掉逾期红色标记**（避免不可还的债造成挫败）；
  4. 每日复习卡数量**不设上限但默认只推 3 张**（其余收在"还有 N 张"折叠里）。
- **异常**：卡片对应的节点被废弃 → 跳过并静默移除。
- **验收**：
  - Given 一个逾期 3 天的节点，When 完成复习并选"不用查就能写"，Then 下次到期时间翻倍且当日分增加；
  - Given 逾期 40 天的节点（h=540），When 打开复习队列，Then 归入"待重建"而非"逾期"。

### F3.1 分区视图（地图首页）

- **优先级**：P0｜**版本**：v0.1
- **入口**：底部 Tab「地图」。
- **展示**：
  - 六个区，每区一行：区名 + **亮度条**（区内加权平均掌握度）+ 该区"已点亮 / 总数"；
  - 点开区 → Topic 折叠列表 → 节点行（名称 + 分层小条 + 状态角标）；
  - 节点行状态角标：`未验证`（C<0.4）/ `在学` / `已巩固`（M>70 且 C>0.6）/ `待复习`（逾期）/ `待重建`。
- **规则**：
  1. **不使用雷达图**（面积随维度数失真、无法下钻、点间无语义），固定用亮度条 + 树；
  2. 亮度条长度 = 区内节点 `M_eff × job_weight` 加权均值，不是简单平均（避免"学了很多低价值节点"看起来很强）；
  3. 默认展开"最近有活动"的区，其余折叠；
  4. 支持按"待复习 / 未验证 / 高价值未学"三种筛选。
- **异常**：某区无任何节点数据 → 显示"这个区还没开放"，不显示 0 长度条。
- **验收**：
  - Given 语言区 20 个节点平均掌握度 18，When 查看地图，Then 该区亮度条约 18% 且显示"6 / 20 已点亮"；
  - Given 筛选"高价值未学"，When 展开，Then 只出现 `job_weight ≥ 4` 且 `M_eff = 0` 的节点。

### F3.2 节点详情

- **优先级**：P0｜**版本**：v0.1
- **入口**：地图任意节点行、三件事卡、复习卡结算后。
- **展示顺序（自上而下）**：
  1. 名称 + `job_weight`；
  2. **分层四条进度条**（D1 概念 / D2 手写 / D3 排错 / D4 决策）+ 总掌握度 + 置信度；
  3. 「你什么时候会用到」—— `definition` + `why` + `in_the_wild`；
  4. 证据时间线（F3.3）；
  5. 常见误区列表（可点开辨析）；
  6. 底部固定操作条：`测一测` / `写示例` / `讲一遍`（按版本开关）。
- **规则**：
  1. 置信度 < 0.4 时，**不显示掌握度数字**，只显示"未验证"+ 灰环；
  2. 四条分层进度条是页面的核心，不允许折叠或排在下面 —— 它回答"我到底卡在哪一层"，这是产品相对其他学习工具最实际的价值；
  3. 前置节点未满足时，在 D3/D4 行旁显示"前置：微任务时序 48/60"，点击可跳转。
- **验收**：
  - Given 节点置信度 0.26，When 打开详情，Then 显示"未验证"且无数字；
  - Given 前置节点掌握度 48，When 查看 D3 行，Then 显示前置提示与跳转。

---

### F3.3 证据时间线

- **优先级**：P1｜**版本**：v0.2
- **规则**：
  1. 倒序，显示：日期、证据类型、难度层、强度增减、是否被门禁打折、链接（可点）；
  2. 被撤销的证据以删除线保留 7 天（让用户看得见"我撤过"，避免分数变动无解释）；
  3. 补记的证据带"补记"角标；
  4. 分页加载，每页 20 条。
- **验收**：Given 撤销一条证据，When 查看时间线，Then 该条显示删除线并在 7 天后消失。

---

### F3.4 误区辨析抽查

- **优先级**：P1｜**版本**：v0.2
- **入口**：节点详情的误区列表（自主）、提交 D3+ 证据时（30% 概率强制）。
- **交互**：给出一句带错误认知的陈述（来自 `misconceptions`），用户判断"对/错"并选一句理由 → 即时判定。
- **规则**：
  1. 强制抽查答错 → 触发它的那条证据强度 ×0.5，并在结果页说明"因为辨析未通过"；
  2. 自主辨析不影响分数，只更新该误区的"已澄清"标记；
  3. 同一误区 14 天内不重复强制抽查。
- **验收**：Given 强制抽查答错，When 查看证据强度，Then 已减半且有文字说明原因。

### F4.1 热力日历与趋势

- **优先级**：P1｜**版本**：v0.2
- **入口**：我的 Tab 顶部。
- **展示**：
  - 近 120 天热力格（深浅 = 分数，非次数），休息日为浅色斜纹，空白日为浅灰；
  - 近 30 日折线（日分 + 7 日移动均线）；
  - 三项分解的堆叠柱（看增量/巩固/结构各自占比变化）。
- **规则**：
  1. 空白日与休息日**视觉可区分**（空白 = 没记录，休息 = 主动选择），避免把休息误读为断签；
  2. 不上"连续天数"大徽章。连续记录只作为一个次要小字，不做视觉焦点 —— 断签焦虑会把用户推向敷衍填卡。
- **验收**：Given 某日标记休息，When 查看热力图，Then 该格为浅色斜纹而非深色空格。

---

### F4.2 周报

- **优先级**：P1｜**版本**：v0.2
- **入口**：每周一上午推送 + 我的 Tab 内「上周复盘」。
- **内容（固定四段，不做花哨排版）**：
  1. 上周均分与环比（有分天数才算分母）；
  2. **高分日的共性**：如"你的 3 个高分日都做了 D3 证据"；
  3. **卡住的地方**：重复未完成的三件事、反复逾期的节点（最多列 3 条）；
  4. 本周建议：1 个具体动作（不是"继续加油"）。
- **规则**：
  1. 第 1 版不接 LLM，全部模板化生成，**宁可话糙也不要说废话**；
  2. 无数据的一周 → 不推送，不生成"你上周什么都没做"这类羞辱性文案。
- **验收**：Given 上周 5 天有分、2 天休息，When 生成周报，Then 均分分母为 5 且文案不出现"断签"。

---

### F4.3 可讲清清单

- **优先级**：P2｜**版本**：v0.3
- **规则**：
  1. 连续 7 天有 ≥70 分的 `explain` 证据，节点标记为"可讲清"；
  2. 清单可导出为 Markdown（作为个人作品集/面试素材）；
  3. 节点降级（衰减或 eol 事件）时，清单标记"待复核"而非直接移除。
- **验收**：Given 某节点连续 7 天讲解 ≥70 分，When 查看清单，Then 出现该节点且可导出。

---

### F5.1 数据导出

- **优先级**：P1｜**版本**：v0.2
- **规则**：
  1. 导出格式：JSON（全量）+ Markdown（可读版）；
  2. 内容：全部证据、掌握度、日分、节点定义；
  3. **一键导出无需确认流程**，不做"确定要离开吗"的挽留。
- **为什么**：学习记录的沉没成本焦虑是这类产品最大的信任隐患，反过来，无摩擦导出是最强的信任信号。

---

### F5.2 提醒与目标设置

- **优先级**：P1｜**版本**：v0.2
- **规则**：
  1. 提醒时间可设，默认关闭（默认开通知是留存作弊，会让人反感）；
  2. 提醒文案中性："今天还欠 2 笔"，不用"你已 3 天没学习"；
  3. 周目标以"证据数"为单位（如每周 8 条 D2 以上证据），不以"时长"为单位。
- **验收**：Given 未开启提醒，When 首次安装后 3 天，Then 不发送任何推送。

---

### F6.1–F6.3 后台（内部）

- **F6.1 节点管理**：节点 CRUD、`definition` 必填校验（少于 15 字或含"了解/熟悉/掌握"直接拒绝——这类词不可验证）、依赖建边与环检测、`job_weight` 维护。
- **F6.2 题库管理**：按节点 × 难度层录题、标 `misconceptions` 来源、看每题正确率（正确率 >95% 或 <20% 的题进复核队列）。
- **F6.3 权重与半衰期**：改 `job_weight` 和 `h` 需二次确认并记录变更日志，因为这两个参数会影响所有用户的历史分数展示（只影响未来计算，不重算历史）。

## 5. 三条核心流程

### 5.1 首次使用（目标：10 分钟内产生 1 条证据 + 第 1 个日分）

1. 选择身份：`零基础` / `在学 1–3 年` / `想查漏补缺`（决定起步推荐，不决定难度）；
2. 三题诊断（跨区各一题），用于给 2–3 个节点定初始掌握度，避免开局全灰；
3. 展示地图（只亮起诊断涉及的节点）；
4. 推 1 个 15 分钟内能完成的动作（"写一个闭包的最小示例"）；
5. 提交 → 日分出现 → 引导语："这就是你的第 1 分，它来自一条真实证据。"

**硬指标**：从打开到首个日分 ≤ 10 分钟，超过则视为 OnInit 失败（要优化，不是加引导）。

### 5.2 一个学习日

```
打开 → 看到今日分（可能还是 0 或空态）
     → 看三件事 → 选一件开始
     → 完成（自测/示例/回填）
     → 证据入账 → 分数实时跳动 → 三件事卡置灰
     → 可选择继续加练或关闭
```

关键交互细节：分数变化必须有**一次可见的跳变动画**（约 400ms），并在旁边浮出"+8 来自：修了 setTimeout 顺序 bug"。这个浮层是整个产品最重要的正反馈，不能省。

### 5.3 一个还债日（没时间学新东西）

```
打开 → 三件事第 1 槽是还债 → 连做 3 张复习卡（约 6 分钟）
     → 日分落在 45–55 区间 → 文案为"今天守住了阵地"
```

这个流程必须成立，否则产品会惩罚"忙但没放弃"的人，而这类人恰恰是最可能长期留下的。

## 6. 状态与异常

| 场景 | 处理 |
|---|---|
| 新用户地图全灰 | 走诊断给初始掌握度，至少点亮 2 个节点 |
| 当日无证据 | 空态文案，不显示 0 分 |
| 分数计算失败 | 显示"计算中"+ 重试，不显示 0 |
| 离线 | 证据入本地队列，恢复后补传；提示"已离线记录" |
| AI 服务不可用 | 讲解入口置灰并说明"暂时不可用，可以先写示例"，不降级成假分数 |
| 节点被废弃 | 从推荐池移除，历史证据保留，不重算历史分 |
| 题库耗尽 | 引导到示例/讲解证据 |
| 跨时区 | 一律按设备本地日期切日；跨时区旅行当天可能"多出半天"，按本地日期为准，不做补偿 |
| 同日多次修改证据 | 5 分钟撤销窗口内重提视为同一条 |

## 7. 文案规范

### 7.1 分数档位（固定五档，禁止改写成夸张语气）

| 区间 | 文案 |
|---|---|
| 0–29 | 今天读了不少，但还没变成能力 |
| 30–49 | 动了，但都在概念层 |
| 50–69 | 有实打实的进展 |
| 70–84 | 今天拿到了 D3 以上的证据 |
| 85–100 | 跨节点连接或架构级决策 |

### 7.2 禁止用语

- 禁止："你太差了""又断了""连续 xx 天，别放弃"（恐惧驱动）
- 禁止："击败了 xx% 的用户"（排行榜变体）
- 禁止：任何把低分等同于人格评价的表述
- 统一：把"你答错了"改为"这里我没听懂，能换个说法吗"；把"失败"改为"这组还不够"

|---|---|---|
| 学习者 | 全部用户端功能 | 是 |
| 内容管理员 | 后台节点/题库/参数 | 是（仅内部账号） |

v0.1 **不做**：社交、好友、排行榜、公开主页、团队空间。理由见 §10。

## 9. 非功能要求

### 9.1 性能
- 今日页首屏（含分数）可交互 < 1.5s（4G）；
- 证据提交到分数更新 < 800ms；
- 地图 180 节点一次性渲染 < 300ms（超过则虚拟列表）。

### 9.2 隐私
- 代码正文不持久化，只存哈希与长度；
- 链接类证据默认仅自己可见，不提供公开分享（避免用户为了展示而伪造证据）；
- 导出即完整导出，不留"仅付费可导出"的钩子。

### 9.3 可靠性
- 日分计算必须幂等：同一批证据重复计算得同一结果；
- 分数一旦冻结（跨天）即不可回写，历史日分是 append-only 的账本。

## 10. v0.1 明确不做的事

| 不做 | 理由 |
|---|---|
| 排行榜 / 好友 | 学习进度与起点强相关，排行榜会把最需要鼓励的人排到最后 |
| 内容推荐流 / 视频课 | 会把产品拉回课程 App 赛道，且这是打不过的战场 |
| 连续打卡徽章 | 断签焦虑会逼出敷衍填卡，污染数据 |
| 付费墙（部分功能锁） | 早期最需要的是"可信"，不是"变现" |
| 团队 / 班级 | 需求真实但会让评分口径变复杂，等个人版验证完再说 |

## 11. 验收总清单

v0.1 上线前逐条打勾：

- [ ] 新用户 10 分钟内能拿到第 1 个日分
- [ ] 任一分数可逐条追溯到具体证据
- [ ] 只刷 D1 证据的节点，掌握度不超过 10
- [ ] 前置未满足时，D3/D4 证据按 50% 计入且有文字说明
- [ ] 置信度 < 0.4 的节点不显示掌握度数字
- [ ] 休息日不计入周均分分母、不清零任何记录
- [ ] 同节点同日同层重复证据只取最大值
- [ ] 撤销证据后分数与掌握度回退正确
- [ ] 离线提交的证据能在恢复后入账且归属正确日期
- [ ] 空态、错误态均不出现"0 分"
- [ ] 冷启动 40 个节点中，随机抽 5 个节点的题目能正常作答并计入证据
- [ ] 全量数据可一键导出为 JSON 与 Markdown
